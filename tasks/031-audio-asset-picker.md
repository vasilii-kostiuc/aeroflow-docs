# Audio Asset Picker: библиотека с папками, прослушиванием, названием и недавними

Status: Done
Bounded context: Audio Catalog (Core — папки, отображаемое название, изменение
деталей ассета), presentation (aeroflow-web — окно выбора, экран
«Аудиобиблиотека»)
Service: aeroflow-core, aeroflow-web
Change type: Domain, Application, API, Frontend (UX)

## Goal

Сделать выбор аудиофайла понятным для администратора: вместо плоского
выпадающего списка технических имён — окно библиотеки, разложенной по папкам,
где файл можно найти по человеческому названию, отфильтровать по языку и
источнику и **прослушать до выбора**, а недавно использованные файлы стоят
первыми.

```text
было:  Select [ gate-a12-en.wav (en) | tts-ru-speech.wav (ru) | tts-ru-speech.wav (ru) | … ]
стало: [Выход A12 · en ▶] [Выбрать…]
         → окно: ┌ Папки ─────────────┐  Вылеты / SU 1234
                 │ Все файлы       42 │  фильтры: язык, источник, поиск
                 │ ▾ Вылеты        12 │  «Недавно использованные»
                 │     SU 1234      4 │  таблица: название / файл / язык /
                 │     U6 2601      4 │           источник / ▶ / выбрать
                 │ ▸ Прибытие       5 │
                 │   Гонги          2 │
                 │ Без папки        9 │
                 └────────────────────┘
```

## Проблема

* файлы выбираются обычным `Select` в двух местах: сегмент конфигурации рейса
  (`flight-definitions/ui/announcement-configs/SegmentModal.tsx`) и языковой
  вариант пресета (`announcement-presets/ui/AnnouncementPresetForm.tsx`, без
  поиска вообще); список плоский, по алфавиту, файлы других языков вперемешку;
* у ассетов нет никакой группировки: гонг, номер выхода, экстренное сообщение и
  фоновая музыка лежат в одном списке. В старой САО библиотека была деревом папок
  (`звуки/вылеты/<рейс>/<язык>/…`, `звуки/числа/<язык>/…`, см.
  `legacy-sao-user-guide.md`), и с сотней рейсов даже группа «Вылеты» была бы
  плоским списком на сотни файлов — фиксированного набора категорий
  недостаточно;
* у `AudioAsset` есть только технический `name`: у загруженного это имя файла
  (`gate-a12-en.wav`), у TTS — slug текста
  (`GenerateAudioAssetHandler::buildName()`), причём slug берёт только
  `[a-z0-9]`, поэтому любой русский TTS-ассет называется `tts-ru-speech.wav` —
  такие ассеты в списке неразличимы;
* прослушать можно только уже выбранный файл, поэтому поиск нужного — это
  «выбрать наугад, послушать, выбрать следующий»;
* нет экрана, где ассеты можно просто посмотреть и привести в порядок;
* запрос списка ассетов и загрузка продублированы в двух features.

## Уже существует (используется, не создаётся заново)

* `AudioAsset` (`src/AudioCatalog/Domain/Entity/AudioAsset.php`) с фабриками
  `upload()` и `generate()` и событиями `AudioAssetUploaded`,
  `AudioAssetGenerated`;
* `GET /api/v1/admin/audio-assets` (активные, по имени), `POST` upload и
  `POST :generate` (`AudioAssetController`), `AudioAssetResult` с полем `source`;
* `ApplicationBus` для command/query из контроллеров (стиль `AudioPrompt`);
* `shared/ui/AudioPreviewButton` — прослушивание по `audioAssetId` с
  авторизацией (`GET /api/v1/admin/audio-assets/{id}/file`);
* загрузка файла прямо из модалки сегмента (`AudioAssetUploader` в
  `SegmentModal.tsx`) и «Озвучить» в форме пресета (задача 021).

## Decisions

### Core: папки (`AudioFolder`)

* новый aggregate root `AudioFolder` в `AudioCatalog\Domain`: `id` (UUID),
  `name`, `parentId` (голый id родителя или `null` для папки верхнего уровня —
  правило #6, без ORM-связи), `createdAt`, `updatedAt`;
* папки — организация библиотеки для администратора, а не бизнес-понятие:
  ни одно правило объявлений от папки не зависит, выбрать в сегмент или пресет
  можно ассет из любой папки. Поэтому в коде нет «системных» папок и нет
  соответствия «тип объявления → папка»;
* язык остаётся свойством ассета и **не** становится уровнем папок (в отличие от
  старой САО, где языковые папки были внутри папки рейса): иначе папки и фильтр
  языка дублировали бы друг друга;
* инварианты:
  * `name` — trim, не пустой, до 100 символов, без `/`;
  * имя уникально среди папок одного родителя без учёта регистра (проверка в
    handler + уникальный индекс по `(parent_id, lower(name))`, для верхнего
    уровня — `NULLS NOT DISTINCT` или эквивалент);
  * глубина — не больше 4 уровней;
  * папку нельзя переместить в саму себя или в своего потомка (проверка
    цепочки предков нового родителя в handler);
  * удалить можно только папку без подпапок и без **активных** ассетов;
    неактивные ассеты такой папки в той же транзакции переносятся в корень
    (`folderId = null`) — иначе администратор видел бы пустую папку, которую
    нельзя удалить;
* порядок — по имени (без учёта регистра); ручная сортировка не вводится;
* use cases через `ApplicationBus`: `CreateAudioFolder`, `UpdateAudioFolder`
  (имя и родитель), `DeleteAudioFolder`, `ListAudioFolders` (плоский список,
  дерево собирает web);
* события: `AudioFolderCreated`, `AudioFolderRenamed`, `AudioFolderMoved`,
  `AudioFolderDeleted`; `Renamed`/`Moved` публикуются только при фактическом
  изменении соответствующего поля;
* миграция создаёт таблицу и стартовые папки верхнего уровня по библиотеке
  старой САО: Вылеты, Прибытие, Дополнительно, Экстренные, Числа, Гонги, Музыка.
  Это обычные папки: их можно переименовать, переместить и удалить.

### Core: ассет в папке

* `AudioAsset` получает `folderId` (голый id папки или `null` — «Без папки»);
* при создании:
  * upload — необязательное поле формы `folderId`;
  * `POST :generate` — необязательное поле `folderId`;
  * озвучивание `text`-сегмента конфигурации рейса (задача 022) и «Озвучить» в
    форме пресета — без папки. Эти ассеты привязываются к сегменту или варианту
    автоматически и почти никогда не выбираются вручную; контекст
    `Announcements` не меняется;
  * при переиспользовании TTS-ассета из кэша его папка не меняется;
* существование папки проверяет application handler через репозиторий
  `AudioFolder` (тот же контекст); неизвестный `folderId` → `404`;
* миграция: колонка `folder_id`, у всех существующих ассетов — `null`.
  Администратор раскладывает их на экране «Аудиобиблиотека».

### Core: отображаемое название (`title`)

* `AudioAsset` получает поле `title` — человекочитаемое название для
  интерфейса. `name` остаётся техническим именем файла (неизменяемым) и в UI
  показывается только вторичной строкой;
* инварианты `title`: обязателен, trim, не пустой, до 255 символов. Уникальность
  **не требуется**: «Выход A12» на `ru` и на `en` — два разных ассета, их
  различает язык;
* значение по умолчанию при создании:
  * upload — необязательное поле формы `title`; если не передано — имя файла
    без расширения, `-` и `_` заменены пробелами (`gate-a12-en.wav` →
    `gate a12 en`);
  * TTS — исходный текст синтеза (нормализованные пробелы, обрезка до 120
    символов с `…`). При переиспользовании из кэша `title` существующего ассета
    не меняется;
* миграция: колонка `title`, backfill по тем же правилам, что и для upload, из
  текущего `name`. Исходный текст старых TTS-ассетов не восстанавливается (в
  ассете хранится только хеш), поэтому они получают название из `name`, а
  администратор переименовывает их на экране «Аудиобиблиотека».

### Core: изменение деталей ассета

* use case `UpdateAudioAsset` (`UpdateAudioAssetCommand { id, title, folderId }`
  через `ApplicationBus`), метод агрегата
  `updateDetails(string $title, ?Uuid $folderId)`;
* идемпотентен: событие `AudioAssetUpdated` (id, title, folderId) публикуется
  только если что-то действительно изменилось. Изменить можно и неактивный
  ассет;
* изменение не влияет на уже созданные `Announcement`: `AudioSequence` хранит
  `audioAssetId`, а не название или папку.

### Core: API

Папки:

* `GET /api/v1/admin/audio-folders` → `[{ id, name, parentId }]`;
* `POST /api/v1/admin/audio-folders` `{ name, parentId? }` → `201`;
* `PATCH /api/v1/admin/audio-folders/{id}` `{ name, parentId }` → `200`
  (переименование и перемещение);
* `DELETE /api/v1/admin/audio-folders/{id}` → `204`;
* ошибки: `404` — папка или родитель не найдены; `409` — имя уже занято у этого
  родителя, удаление непустой папки; `422` — пустое или слишком длинное имя,
  `/` в имени, превышение глубины, перемещение в себя или потомка.

Ассеты:

* `AudioAssetResult` получает `title` (обязательное) и `folderId` (nullable);
  `name` остаётся — изменение контракта обратно совместимое;
* `GET /api/v1/admin/audio-assets` сортирует по `title`, форма ответа (массив)
  не меняется;
* `POST /api/v1/admin/audio-assets` принимает необязательные поля формы `title`
  и `folderId`; `POST …:generate` — необязательное `folderId`;
* новый `PATCH /api/v1/admin/audio-assets/{id}` `{ "title": "…", "folderId": "…" | null }`
  → `200` с `AudioAssetResult`; `404` — ассет или папка не найдены; `422` —
  пустое или слишком длинное название.

Фильтры и пагинация на сервере в этом срезе **не вводятся**: активных ассетов
десятки, web загружает оба списка целиком и фильтрует на клиенте. Серверные
`folderId/languageCode/source/q` и пагинация вводятся вместе с импортом
библиотеки старой САО, когда объём станет сотнями файлов (см. Out of Scope).

### Web: feature `audio-assets`

* новая feature `audio-assets` — единственный владелец API ассетов и папок в
  web: `audioAssetApi.ts` (list, upload, update, generate),
  `audioFolderApi.ts` (list, create, update, delete), query keys, хуки, типы
  `AudioAsset` (`id`, `title`, `name`, `languageCode`, `folderId`, `source`,
  `active`) и `AudioFolder`, сборка дерева и путей из плоского списка;
* продублированные запросы и загрузчик из `flight-definitions` и
  `announcement-presets` переезжают сюда; эти features импортируют публичный
  `AudioAssetPicker` из `audio-assets` (явная причина межфичевого импорта, как у
  `announcement-presets`);
* везде, где ассет показывается текстом (подписи сегментов в
  `model/announcementConfig.ts`, строки вариантов пресетов), выводится `title`, а
  не `name`.

### Web: общий браузер библиотеки

Окно выбора и экран «Аудиобиблиотека» строятся на одном компоненте:

* **дерево папок** слева: сверху «Все файлы» (вся библиотека), затем папки
  верхнего уровня, внизу «Без папки» (`folderId = null`); раскрытие и
  сворачивание; у каждого узла — счётчик ассетов в нём и во всех его подпапках
  с учётом фильтров языка, источника и поиска; папки с нулём показываются
  приглушённо, но остаются кликабельными. На узком экране дерево превращается в
  `Select` с путями (`Вылеты / SU 1234`);
* над таблицей — «хлебные крошки» пути выбранной папки, по ним можно
  подняться выше;
* **таблица** выбранной папки: сначала её подпапки (клик открывает папку), затем
  ассеты, лежащие непосредственно в ней. В режиме «Все файлы» и при поиске —
  плоский список всех подходящих ассетов с колонкой пути папки;
* строка ассета: название (крупно) и имя файла (вторичной строкой), язык, бейдж
  источника, ▶;
* фильтр языка, фильтр источника («Все / Загруженные / Озвученные»), поиск по
  `title` и `name` без учёта регистра; при непустом поиске поиск идёт по всей
  библиотеке, а не только по выбранной папке;
* одновременно звучит не больше одного превью: запуск другого останавливает
  предыдущее; закрытие окна или уход с экрана останавливает звук.

### Web: `AudioAssetPicker`

Замена `Select` в `SegmentModal` и в `AnnouncementPresetForm`. Потребитель
передаёт пикеру язык варианта и **ключ места выбора**: `segment:<тип объявления>`
для сегмента рейса, `preset:supplementary` и `preset:emergency` для пресетов.

* **поле**: название выбранного ассета, бейдж языка, кнопка прослушивания и
  кнопка «Выбрать…» / «Изменить…». Если выбранного id нет в списке активных —
  «Файл недоступен» (конфигурация всё равно покажет неготовность);
* **окно выбора** (modal) — общий браузер библиотеки плюс выбор по клику на
  строку ассета или по кнопке «Выбрать»;
* **какая папка открыта при открытии окна** — по приоритету:
  1. папка уже выбранного ассета (его строка подсвечена);
  2. папка, из которой в последний раз выбирали файл для этого ключа места
     выбора (сегмент посадки открывается там, где выбирали для посадки в прошлый
     раз);
  3. «Все файлы».

  Папка, которой больше нет, пропускается. Последняя папка по ключу места
  выбора — локальное предпочтение пользователя (Zustand, см. ниже);
* фильтр языка — по умолчанию язык редактируемого варианта, переключатель
  «Все языки»; ассет другого языка выбрать можно, но он помечен бейджем
  «другой язык» (как сейчас в `SegmentModal`);
* «Загрузить файл» внутри окна (перенесённый `AudioAssetUploader` с полями
  «Название» и «Папка»; папка по умолчанию — открытая в окне, для «Все файлы» —
  «Без папки»); загруженный файл сразу выбирается;
* **«Недавно использованные»** — блок над таблицей, до 8 ассетов, в порядке
  последнего выбора:
  * подчиняется только фильтру языка: блок — быстрый доступ поперёк папок и
    источников, иначе он пропадал бы при каждой смене папки; при непустом
    поиске блок скрыт — результаты поиска идут одним списком;
  * id, которых нет в текущем списке активных ассетов, молча пропускаются и
    вычищаются из хранилища.

Недавние ассеты и последняя папка по ключу места выбора — локальные
предпочтения пользователя, а не серверные данные: хранятся в одном Zustand-store
с persist в `localStorage`, ключ содержит id пользователя
(`web/architecture.md`, раздел Zustand); при выходе из сессии не очищаются.

### Web: экран «Аудиобиблиотека»

* маршрут `/audio-assets`, пункт навигации «Аудиобиблиотека», начинается с
  `shared/ui/PageHeader`; по умолчанию открыты «Все файлы»;
* общий браузер библиотеки плюс действия:
  * папки: «Новая папка» (в открытой папке), переименовать, «Переместить в…»
    (выбор папки в дереве; сама папка и её потомки недоступны), удалить — с
    подтверждением; у непустой папки кнопка удаления неактивна с подсказкой,
    серверный `409` показывается уведомлением;
  * ассеты: изменить (modal с полями «Название» и «Папка»), «Загрузить файл» в
    открытую папку;
  * серверные `409/422` показываются у соответствующих полей;
* открытая папка, фильтры и поиск хранятся в URL (`web/architecture.md`, React
  Router).

### Доработка после первой проверки: управление прямо в дереве, перетаскивание

Первая версия прятала действия с папкой за «⋮» у «хлебных крошек», и
управление папками было трудно найти. Доработка:

* у каждой папки в дереве — своё меню «⋮»: «Новая подпапка», «Переименовать»,
  «Переместить в…», «Удалить» (только пустая, иначе пункт неактивен с
  пояснением); в окне папки предлагаются только допустимые родители — без неё
  самой, её подпапок и мест глубже лимита;
* у файла — меню «⋮»: «Изменить», «Переместить в…»;
* выбор нескольких файлов флажками (плюс «выбрать все» в текущем виде) и
  панель «Выбрано: N · Переместить в… · Снять выделение»; выделение
  сбрасывается при смене папки или фильтров;
* **перетаскивание**: файл (или все выбранные, если тащат выбранный) — на папку
  в дереве, на подпапку в таблице или на «Без папки»; папка — на другую папку
  или на «Все файлы» (верхний уровень). Цели, которые сервер отклонит (своя
  подпапка, превышение глубины, текущее место), не подсвечиваются и не
  принимают drop. Свёрнутая папка под курсором раскрывается через ~0,6 с.
  Перенос отражается в интерфейсе сразу и откатывается с уведомлением, если
  сервер отказал. Используется встроенный HTML5 drag and drop — на сенсорных
  экранах он не работает, там остаётся «Переместить в…»;
* групповой перенос на сервере — `POST /api/v1/admin/audio-assets:move`
  `{ assetIds, folderId }` (use case `MoveAudioAssets`): все или ничего — один
  неизвестный id → `404` и ни один файл не перенесён; пустой список или больше
  500 → `422`;
* «Новая папка» в окне выбора файла — создаётся в открытой папке, и окно сразу
  её открывает.

## Out of Scope

* импорт библиотеки старой САО (стартовые папки только повторяют её верхний
  уровень);
* серверные фильтры, поиск и пагинация списков — вместе с импортом;
* перетаскивание на сенсорных экранах и с клавиатуры (есть «Переместить в…»);
* удаление непустой папки (например, с переносом содержимого в родительскую);
* ручной порядок папок;
* автоматическая раскладка озвученных ассетов по папкам;
* длительность файла (не хранится в модели);
* деактивация ассета из UI (эндпоинта нет; нужно сначала решить, как
  предупреждать о ломающихся конфигурациях и пресетах);
* «где используется» у ассета (ссылки живут в контексте Announcements — это
  межконтекстный read, отдельное решение);
* исправление slug в `buildName()` для кириллицы — `name` технический и после
  этой задачи в UI вторичен.

## Acceptance Criteria

Core:

* после миграции есть 7 стартовых папок верхнего уровня; все существующие
  ассеты — без папки и с `title` из `name`;
* папку можно создать, переименовать, переместить и удалить через API;
* повтор имени у того же родителя (без учёта регистра) → `409`; то же имя у
  разных родителей допустимо;
* перемещение папки в себя или в потомка и превышение глубины 4 → `422`;
* удаление папки с подпапками или активными ассетами → `409`; удаление папки,
  где остались только неактивные ассеты, переносит их в корень;
* upload без `title`/`folderId` даёт название из имени файла и «Без папки», с
  ними — переданные значения; неизвестный `folderId` → `404`;
* TTS-генерация даёт `title` = текст (обрезанный до 120 символов); повторная
  генерация того же текста возвращает тот же ассет с прежними названием и
  папкой;
* `PATCH …/audio-assets/{id}` меняет название и папку; повтор с теми же
  значениями не публикует `AudioAssetUpdated`; пустое название → `422`;
* `name` и `AudioSequence` существующих объявлений не меняются.

Web:

* в сегменте рейса и в варианте пресета файл выбирается через окно библиотеки,
  а не через выпадающий список;
* окно показывает дерево папок со счётчиками и «хлебные крошки»; открывается в
  папке выбранного ассета, иначе в последней папке для этого места выбора, иначе
  на «Все файлы»;
* по умолчанию окно показывает ассеты языка варианта; «Все языки» показывает
  остальные с пометкой «другой язык»;
* работают фильтр источника и поиск по названию и имени файла; поиск идёт по
  всей библиотеке и показывает путь папки;
* любой ассет можно прослушать из строки таблицы до выбора; одновременно звучит
  не более одного;
* блок «Недавно использованные» показывает последние выбранные ассеты
  (не более 8) с учётом языка, независимо от папки и источника, переживает
  перезагрузку страницы и не показывает неактивные ассеты;
* загрузка из окна принимает название и папку и сразу выбирает загруженный
  файл;
* экран «Аудиобиблиотека» позволяет создавать, переименовывать, перемещать и
  удалять папки, а у ассетов — искать, фильтровать, слушать, загружать,
  переименовывать и переносить в другую папку; открытая папка и фильтры — в URL;
* во всех подписях ассетов в интерфейсе выводится `title`;
* запросы ассетов и папок живут только в feature `audio-assets`.

## Verification

```bash
# aeroflow-core
php bin/phpunit tests/Unit tests/Application
php bin/phpunit tests/Functional/AudioCatalog

# aeroflow-web
npm run lint && npm run typecheck && npm run test:run && npm run build
```

Ручная проверка: создать `Вылеты / SU 1234`, загрузить туда файл с названием;
выбрать его в сегменте посадки — при следующем открытии окна для посадки
открывается `Вылеты / SU 1234`; переименовать ассет — новое название видно в
сегменте рейса и в пресете; попытаться удалить непустую папку — отказ;
переместить `Вылеты` внутрь `SU 1234` — отказ.
