# Announcement Editor: View by Default, Edit One Variant at a Time

Status: Done  
Bounded context: Announcements (presentation only)  
Service: aeroflow-web  
Change type: Frontend (UX)

## Goal

Сделать экран «Объявления рейса» (вкладка карточки рейса) безопасным и
обозримым: админ видит все языковые варианты типа объявления компактно, правит
**один вариант за раз** и не может молча потерять несохранённые правки.

## Проблема

Экран держал все варианты всех языков в режиме редактирования одновременно:

* пять независимых точек сохранения на одном экране («Сохранить настройки» и
  «Сохранить вариант» у каждого языка) без индикатора несохранённых изменений —
  отредактировать два варианта и сохранить один значит потерять второй;
* переключение вкладки типа объявления или уход со страницы молча сбрасывали
  черновики;
* состояние дублировалось: «активно», «готово для диспетчера», тумблер
  «Включено» и бейдж на вкладке; «включён» и тумблер «Вариант включён»;
* порядок языков задавался числовым полем, а не стрелками, как у сегментов;
* удаление варианта не спрашивало подтверждения;
* в интерфейсе был текст для разработчика и сокращения («1 сегм.»); язык `en`
  отображался кодом, а не названием.

## Решение (вариант B)

Без изменений API и core. Экран остаётся на существующих эндпоинтах
`PATCH …/announcement-configs/{id}` и `POST|PATCH|DELETE …/variants`.

### Просмотр по умолчанию

Каждый языковой вариант — компактная строка только для чтения: язык, сводка
содержимого (текст или состав сегментов), прослушивание, если вариант — один
файл. Действия в строке применяются **сразу**, без отдельной кнопки сохранения:

* тумблер включения варианта;
* перестановка ↑↓ (перенумерация `sortOrder` затронутых вариантов);
* удаление — с подтверждением.

Настройки типа объявления: тумблер «Включено» применяется сразу; интервал повтора
(только «Продолжение регистрации») — поле с кнопкой сохранения, активной лишь при
изменении. Статус типа — один бейдж: «Готово», «Требует настройки» (с причинами)
или «Выключено».

### Редактирование одного варианта

«Изменить» раскрывает строку в редактор (язык + сегменты) с «Сохранить / Отмена».
Пока открыт редактор, открыть второй или начать «Добавить язык» нельзя. Редактор
правит только язык и сегменты; включение и порядок варианта остаются действиями
строки и при сохранении берутся из актуальных данных сервера.

Сохранение варианта озвучивает текстовые сегменты (задача 022) и может занять
несколько секунд — редактор об этом предупреждает.

### Защита от потери правок

Пока в открытом редакторе есть несохранённые изменения:

* переключение вкладки типа объявления спрашивает подтверждение;
* уход со страницы внутри приложения (включая вкладки «Карточка / Объявления»)
  блокируется с подтверждением (`useBlocker`);
* закрытие или перезагрузка вкладки браузера предупреждается (`beforeunload`).

## Out of Scope

* одна кнопка сохранения на весь тип объявления (вариант C — требует
  bulk-эндпоинта в core);
* обзорная матрица «тип × язык» (вариант D);
* inline-редактирование текста без модалки сегмента.

## Acceptance Criteria

* варианты отображаются строками только для чтения; одновременно открыт не более
  одного редактора;
* включение, перестановка и удаление варианта применяются без отдельного
  сохранения; удаление — после подтверждения;
* тумблер типа объявления применяется сразу; интервал повтора сохраняется только
  при изменении;
* несохранённый черновик не теряется молча ни при переключении вкладки типа, ни
  при навигации, ни при закрытии вкладки браузера;
* язык отображается названием (`English · en`), текста для разработчика нет;
* lint, typecheck, tests, build зелёные.

```bash
npm run lint && npm run typecheck && npm run test:run && npm run build
```
