# Раскладка существующих аудиофайлов по папкам

Status: Done
Bounded context: Audio Catalog (запись через его use cases); чтение использования
из Announcements и Flight Operations — только в консольной инфраструктуре
Service: aeroflow-core
Change type: Infrastructure (console), maintenance

## Goal

После задачи 031 все существующие файлы лежат «Без папки», а у озвученных TTS
название собрано из технического slug («tts ro MD stima i pasageri…», русские —
«tts ru speech»). Нужно разложить их по папкам и дать читаемые названия, не
перебирая сотни файлов руками.

## Решение

Консольная команда `app:audio-library:organize` (`--dry-run` — только показать
план). Место файла определяется тем, где он используется:

| использование                      | папка                    | название            |
|------------------------------------|--------------------------|---------------------|
| экстренный пресет                  | `Экстренные`             | имя пресета         |
| дополнительный пресет              | `Дополнительно`          | имя пресета         |
| сегмент объявления вылета          | `Вылеты / <номер рейса>` | текст сегмента      |
| сегмент объявления прилёта         | `Прибытие / <номер рейса>` | текст сегмента    |

* Текст сегмента — тот, из которого файл был озвучен (задача 022); название по
  тому же правилу, что при генерации (`AudioAsset::titleFromText`, до 120
  символов).
* Переносятся только файлы без папки, меняются только названия по умолчанию
  (из имени файла) — то, что администратор уже разложил или переименовал, не
  трогается. Повторный запуск безопасен; пригодится и позже, когда новые
  сегменты озвучиваются «Без папки».
* Не используемые нигде файлы и файлы, чьи места использования расходятся (два
  рейса, пресет и рейс), остаются как есть и перечисляются в выводе.
* Папки ищутся по имени без учёта регистра и создаются, если их нет.
* Запись — через use cases Audio Catalog (`CreateAudioFolder`, `MoveAudioAssets`,
  `UpdateAudioAsset`): инварианты папок и доменные события как обычно. Чтение
  использования — SQL в консольной инфраструктуре рядом с сидерами, не в
  application-коде.

Не миграция: план виден заранее (`--dry-run`), решение о применении остаётся за
человеком, и команду можно запускать повторно.

## Запуск

```bash
docker exec -u www-data aeroflow_core_app php bin/console app:audio-library:organize --dry-run -v
docker exec -u www-data aeroflow_core_app php bin/console app:audio-library:organize
```

## Acceptance Criteria

* dry-run печатает план по папкам и список оставленных файлов, ничего не меняя;
* применение раскладывает файлы по таблице выше и меняет названия по умолчанию;
* файлы в папке и переименованные файлы не перемещаются и не переименовываются;
* повторный запуск ничего не меняет.
